# IBR Invest — панель управления портфелями инвесторов

Закрытый кабинет IBR Group. **Администратор** вручную ведёт деньги инвесторов, **инвестор** видит только свои данные в режиме «только чтение» — в виде квартальных отчётов (замороженных снимков).

Стек: Next.js 15 (App Router, серверный режим), React 19, Tailwind 3.4, Prisma + SQLite, `jose` (JWT), `bcryptjs`, `zod`, `recharts`, `lucide-react`, Vitest.

## Быстрый старт

```bash
npm install
cp .env.example .env        # заполните AUTH_SECRET, ADMIN_PHONE, ADMIN_PASSWORD
npm run db:push             # создаёт prisma/dev.db
npm run db:seed             # администратор (+ демо при SEED_DEMO=1 или флаге --demo)
npm run dev                 # http://localhost:3100
```

Демо-данные: `npm run db:seed -- --demo` создаёт инвесторов (в том числе «Иванов Иван Иванович»: пополнение 190 000 ₽ → покупка 100 000 ₽ → доход 2 500 ₽; пароль всех демо-инвесторов `Demo#2026`, логины `+79990000001` … `+79990000006`).

## Денежная логика (`lib/ledger.ts`)

Все суммы — целые копейки (`Int`). Операции: `DEPOSIT`, `TRANSFER` (остаток → вложено), `PURCHASE`, `INCOME`.

- Общая сумма = Σ пополнений + Σ дохода
- Вложено = Σ переносов + Σ покупок
- Доход = Σ дохода
- Остаток = Общая − Вложено (может быть отрицательным — в форме покупки показывается предупреждение)

Сумма покупки = `round(количество × цена)` в целых числах (BigInt, без float); количество хранится строкой (до 6 знаков). Максимум одной операции — 20 000 000 ₽ (ограничение `Int` в Postgres).
Журнал операций только на добавление: редактирования и удаления нет.

## Кварталы

Кнопка «Сформировать квартальные доступы» (главная админки и `/admin/quarters`):

1. квартал блокируется — сервер отклоняет любые операции с датой (для дохода — месяцем) в этом квартале;
2. для каждого **активного** инвестора создаётся отчёт: токен `crypto.randomBytes(24)` (base64url) и JSON-снимок (счётчики, активы, доход по месяцам, операции);
3. создаётся уведомление в кабинете (e-mail/SMS не отправляются);
4. повторное нажатие для закрытого квартала отклоняется (409).

Инвестор видит **последний снимок**, а не живые данные; до первого отчёта показывается заглушка. Ссылка `/report/[токен]` открывается только владельцу-инвестору или администратору (иначе вход / 404). «Скачать PDF» — `window.print()` с отдельными стилями печати (A4).

## Безопасность

- Свой auth: пароли `bcryptjs` (12 раундов), сессия — JWT (`jose`, HS256, секрет `AUTH_SECRET`) в httpOnly cookie `SameSite=Lax`, `Secure` в продакшене.
- `middleware.ts` защищает `/admin/*`, `/cabinet/*`, `/report/*`, но **каждый** route handler и страница заново проверяют роль на сервере и перечитывают пользователя из БД; запросы инвестора всегда фильтруются по `userId` сессии.
- Операции списания (покупка, перенос) требуют повторного ввода пароля администратора; проверка `bcrypt.compare` выполняется на сервере при каждом запросе.
- Фото: только JPEG/PNG/WebP по сигнатуре (magic bytes), до 5 МБ, хранятся в `storage/uploads/` вне `public`, отдаются через `/api/files/[id]` с проверкой владельца.
- Ограничение попыток входа (в памяти процесса), валидация входных данных через `zod`.

## Деплой

1. Node 20+ (разработка на Node 24). Задайте переменные окружения из `.env.example` (сильный `AUTH_SECRET`, `COOKIE_SECURE=true` за HTTPS).
2. `npm ci && npm run db:push && npm run db:seed && npm run build && npm start`.
3. Сохраняйте и бэкапьте `prisma/dev.db` и `storage/uploads/` (или смонтируйте их как volume). Сервис — один процесс с файловой БД; для нескольких инстансов перейдите на Postgres: смените `provider` в `prisma/schema.prisma` и `DATABASE_URL` (роли/статусы хранятся строками, схема переносима).
4. Приложение должно работать в серверном режиме (не `next export`).
